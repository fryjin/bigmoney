# 2.5D 大富翁游戏综合开发说明

**文档版本：** 1.0  
**目标载体：** iPad 横屏优先的 HTML5/PWA 游戏  
**代码托管：** GitHub  
**部署：** Cloudflare Pages  
**规则状态：** 基本冻结，不在本阶段重新设计

---

## 1. 项目目标

开发一款2～4名玩家在同一台iPad上游玩的2.5D微缩城市大富翁。产品需要同时满足：

- 规则稳定、结算准确、流程不中断；
- 城市场景精致但不过度依赖实时3D；
- iPad Safari和主屏幕PWA中运行流畅；
- 代码、规则、流程、UI与美术资产彼此解耦；
- GitHub提交后可自动部署到Cloudflare预览和正式环境；
- 后续更换场景、美术皮肤或UI，不推翻规则核心。

“简单”只体现在信息组织和操作步骤上，不能以缺少建筑设计、城市细节、反馈动画或组件状态为代价。

## 3. 最终技术选型

| 层级 | 选择 | 职责 |
|---|---|---|
| 构建 | Vite | 开发服务器、打包、资源拆分 |
| 语言 | TypeScript | 全项目强类型 |
| 游戏场景 | Phaser 4 | 城市、建筑、棋子、镜头、骰子、小游戏 |
| 流程编排 | XState 5 | 回合、响应窗口、中断、恢复 |
| 规则核心 | 纯TypeScript | 金额、资产、移动、结算、破产、胜利 |
| UI | Vue 3 | HUD、上下文面板、Modal、设置和总结 |
| DOM动画 | Anime.js | 面板、数字、卡片和页面动效 |
| 地图编辑 | Tiled | 等距场景位置、图层、锚点和路径节点 |
| 配置校验 | Zod | JSON结构、引用和版本校验 |
| 存档 | IndexedDB | 快照、事件日志、设置 |
| 离线 | Service Worker/PWA | 资源缓存、主屏幕运行 |
| 部署 | GitHub + Cloudflare Pages | 分支预览、正式发布 |

## 4. 总体架构

```text
玩家输入
  ↓
GameCommand
  ↓
XState 流程状态与权限校验
  ↓
Game Core 规则计算
  ↓
DomainEvent
  ↓
GameState 更新 + 稳定节点存档
  ↓
PresentationCue
  ↓
Phaser / Vue / Anime.js 播放表现
  ↓
PRESENTATION_DONE
  ↓
XState继续下一结算步骤
```

### 4.1 核心原则

- 游戏真实状态只有一份，位于规则层；
- 动画不决定规则，不在动画结束时扣款或计算租金；
- Vue只展示和收集选择；
- Phaser只呈现场景和交互对象；
- XState只编排流程，不计算经济数值；
- 随机数统一注入并保存种子；
- 一个时间点只能有一个活动结算步骤；
- 中断流程完成后必须恢复到明确状态。

## 5. 技术线

### 5.1 Game Core

负责：

- 玩家、金币、位置和状态；
- 地图节点和移动模式；
- 地产购买、升级和租金；
- 卡片效果和响应结果；
- 股票和合作项目；
- 随机事件；
- 强制付款、清算和破产；
- 大轮结算和胜利。

输入输出：

```ts
handleCommand(state, command, randomProvider)
  => { nextState, events }
```

禁止依赖浏览器、DOM、Phaser、Vue和Anime.js。

### 5.2 Game Flow

主状态：

```text
setup
roundStart
turnStart
jailDecision
preRoll
rolling
postRoll
moving
resolvingPath
resolvingDestination
awaitingDecision
cardResponse
payment
liquidation
turnEnd
roundEnd
finished
```

独立子Actor：

- PropertyDecisionActor
- StockMarketActor
- ProjectInviteActor
- CardReplacementActor
- DefenseWindowActor
- PaymentActor
- LiquidationActor
- MinigameActor

### 5.3 Phaser场景

建议场景：

- BootScene：启动和能力检测；
- PreloadScene：资源加载与进度；
- TownScene：主棋盘；
- MiniGameScene：小游戏容器或独立子场景；
- ResultScene：结算表现；
- DebugScene：开发工具，仅DEBUG启用。

Phaser负责：

- 等距地图和深度排序；
- 棋子逐格移动；
- 相机缩放、跟随和边界；
- 道路高亮；
- 建筑替换与升级；
- 旗帜、粒子、车辆和行人；
- 骰子和小游戏。

### 5.4 Vue UI

常驻UI仅保留：

- 其他玩家简略状态；
- 当前玩家摘要；
- 当前阶段提示；
- 手牌入口；
- 骰子主操作；
- 资产入口。

非阻断内容统一进入一个 `ContextPanel`。同一时间只显示一个上下文：地产、股票、项目、事件、监狱、付款或资产。

Modal只用于必须完成后才能继续的决策：购买、合作邀请、防御、四选三、清算等。

### 5.5 数据和配置

配置拆分：

```text
game-rules.json
map-001.json
properties.json
cards.json
stocks.json
stock-outcomes.json
projects.json
events.json
minigames.json
localization-zh.json
```

所有配置必须包含 `configVersion`，启动时执行Zod校验和引用完整性校验。

### 5.6 存档

采用：

- 有效操作追加轻量领域事件；
- 每个回合结束保存完整快照；
- 中断流程完成、破产、大轮结束、进入后台时保存稳定快照；
- 不要求恢复动画中间帧；
- 存档包含配置版本、规则版本、随机种子和迁移版本。

## 6. 设计线

### 6.1 视觉方向

采用“精致微缩城市＋轻量桌游控制台”。视觉目标：

- 2.5D等距视角；
- 固定光源和统一阴影方向；
- 青绿、灰蓝、米白为主，少量珊瑚橙和黄色强调；
- 建筑类型明确，不以同一模型换色代替；
- UI克制，但每个状态完整；
- 隐藏UI后，棋盘仍是一张完成度足够的城市插画。

### 6.2 场景资产生产

不在浏览器中用代码拼建筑。建议生产流程：

```text
Blender / Illustrator / 专业绘制
→ 固定等距相机与光源
→ 输出透明WebP或AVIF
→ 裁切透明边距
→ 生成纹理图集
→ Tiled编排
→ Phaser加载
```

普通地产必须有：空地、基础、一级、二级、三级。特殊格建筑应通过轮廓识别：交易所、警署、活动中心、市政设施、幸运商店等。

### 6.3 首版资产最低清单

- 10套普通地产建筑，每套0～3级；
- 2套股票交易所；
- 2套卡片建筑；
- 3套事件场所；
- 2套小游戏建筑；
- 2套公共设施；
- 1套警署/监狱；
- 起点、终点标志；
- 树木、灌木、花坛、车辆、路灯、长椅、路牌、消防栓、行人等城市装饰。

### 6.4 深度与锚点

每个对象记录脚底锚点，默认：

```text
depth = anchorY
```

地图图层：

```text
00 地面与水体
10 道路和地块
20 建筑与植被
30 棋子、车辆和行人
40 旗帜与产权标记
50 路径与交互高亮
60 短时粒子和特效
```

### 6.5 UI设计原则

- 城市画面占据绝对主体；
- 白色大面板不常驻堆叠；
- 当前玩家信息比其他玩家完整；
- 骰子是唯一一级操作；
- 金额和决策结果在3秒内可读懂；
- 面板结构保持统一，但不同玩法有类型化视觉；
- 所有点击目标适合iPad触控；
- 支持标准动画、快速动画和减少动态效果。

### 6.6 动画边界

- Phaser Tween：棋子、建筑、旗帜、镜头、路径、粒子、骰子；
- Anime.js：DOM面板、数字、卡片、Toast和转场；
- 不允许两个动画系统控制同一对象；
- 所有长动画可点击加速；
- 动画中断不得破坏状态。

## 7. 技术线与设计线的接口契约

每个美术对象必须提供：

- 唯一资源ID；
- 透明贴图；
- 原始尺寸；
- 脚底锚点；
- 交互区域；
- 阴影是否烘焙；
- 所属图集；
- 建议显示缩放；
- 状态变体；
- Tiled对象名。

示例：

```json
{
  "assetId": "property_a1_level_2",
  "atlas": "buildings-01",
  "frame": "property_a1_level_2.webp",
  "size": { "width": 420, "height": 360 },
  "anchor": { "x": 0.5, "y": 0.91 },
  "interactionPolygon": [[80,310],[210,250],[360,310],[210,355]],
  "shadowBaked": true,
  "tiledType": "PROPERTY_BUILDING"
}
```

设计稿未提供上述信息时，不进入正式资源库。

## 9. 性能预算

### 9.1 目标

- 默认目标60 FPS；
- 复杂结算允许短时降至30 FPS，但不能影响输入；
- 首屏核心资源尽量控制在15 MB以内；
- 完整MVP资源建议控制在80～120 MB缓存范围内；
- 单张纹理尺寸优先不超过2048×2048，必要时按设备能力评估4096；
- Canvas渲染倍率默认1.5，最高2.0，不直接使用完整设备DPR。

### 9.2 质量档

- High：较新iPad，完整粒子和背景活动；
- Standard：默认；
- Economy：降低渲染倍率、粒子、环境对象和滤镜。

### 9.3 禁止项

- 超大整城单图；
- 大量实时模糊、发光和景深；
- 每帧创建对象；
- 高频DOM布局；
- 大量独立SVG DOM节点；
- 未压缩音频和透明边距过大的贴图。

## 11. GitHub与Cloudflare工作流

### 分支

- `main`：正式环境；
- `develop`：集成环境；
- `feature/*`：功能；
- `design/*`：UI和资源；
- `fix/*`：缺陷。

### Pull Request门槛

- 类型检查通过；
- 单元测试通过；
- 配置校验通过；
- 技术或UI修改附说明；
- UI修改附iPad截图；
- 规则行为变化必须明确标注并由产品确认。

### Cloudflare

- PR/分支：预览部署；
- `develop`：测试环境；
- `main`：正式环境；
- 静态资源使用内容哈希和长缓存；
- HTML与Service Worker使用短缓存或重新验证。

## 13. 风险与控制

| 风险 | 控制方式 |
|---|---|
| 美术精致度不足 | 技术切片使用正式质量资产，不再使用几何占位稿验收风格 |
| Phaser新版本风险 | 固定版本，独立升级分支，保留回归截图和真机测试 |
| 流程卡死 | XState显式状态、单一结算队列、场景测试 |
| 重复结算 | Command幂等键、步骤ID、输入锁和事件日志 |
| Safari后台问题 | 稳定节点快照、场景重建、WebGL恢复 |
| 资源过大 | 图集、透明边距裁切、分包、设备质量档 |
| Codex跑偏 | AGENTS.md边界、规则冻结文件、模块依赖检查 |
| UI遮挡城市 | 常驻UI上限和单一ContextPanel机制 |
