# Big Money UI 与 2.5D 视觉设计规范 v1.0

> 状态：第一阶段设计基线  
> 适用载体：iPad 横屏优先的 HTML5 游戏  
> 技术边界：Phaser 场景 + Vue UI + XState 流程 + 纯 TypeScript 规则核心  
> 规则边界：沿用已冻结的 36 格、2～4 人本地同屏、地产/卡片/股票/合作项目/事件/小游戏/监狱/清算/破产规则；本规范不新增或修改玩法规则。

---

## 1. 设计目标

Big Money 的首要体验不是“模拟真实城市”，而是让玩家在一座精致、清晰、可读的微缩小镇中完成回合制经营与对抗。

设计必须同时满足四个目标：

1. **一眼可读**：玩家能迅速确认当前回合、棋子位置、道路方向、目标建筑和可执行操作。
2. **简单但不简陋**：减少无效信息，不减少建筑、材质、光影和交互反馈的完成度。
3. **城市即棋盘**：道路、建筑入口、街区和公共设施直接承担棋盘语义，而不是在城市背景上覆盖一圈普通按钮。
4. **表现与规则分离**：任何视觉动画都不能成为规则判定依据，跳过动画或恢复存档后，规则状态仍保持正确。

### 1.1 体验关键词

- Miniature City
- Cozy Strategy
- Polished Toy World
- Clean Board Game
- Friendly Competition
- Clear Turn Feedback

### 1.2 明确避免

- 低成本几何块建筑
- 大量白色后台卡片覆盖地图
- 粗黑描边的幼儿卡通风
- 写实金融终端或商务后台风
- 全屏玻璃拟态
- 同一栋建筑仅换颜色复用
- 路线上悬浮大量圆点作为主要棋盘表达
- 依赖长动画掩盖素材不足

## 2. 设备与画布基线

### 2.1 设计基准

| 项目 | 基线 |
|---|---|
| 主设计尺寸 | 1194 × 834 px |
| 方向 | 横屏 |
| 最小逻辑宽度 | 1024 px |
| 推荐渲染比例 | 1.5～2.0，按设备性能动态选择 |
| 安全边距 | 左右 24 px，上下 20 px |
| 触控最小热区 | 44 × 44 px |
| 主要按钮最小高度 | 52 px |

### 2.2 响应式策略

设计不通过缩小全部元素适配不同尺寸，而采用三段式策略：

1. **场景保持比例**：城市棋盘按等比缩放，不能拉伸。
2. **HUD 贴边重排**：玩家状态、控制台和上下文面板按安全区重新定位。
3. **信息降级**：较小屏幕只隐藏次级文字，不隐藏回合状态、余额、骰子和关键决策。

### 2.3 横竖屏

- 正式游戏仅支持横屏主体验。
- 竖屏打开时显示旋转设备提示，不强行重排完整棋盘。
- 旋转提示必须提供“继续恢复横屏”的清晰引导。

## 3. 整体视觉方向

### 3.1 风格定义

采用 **精致微缩城市 2.5D 等距风格**：

- 固定等距视角或近似等距视角；
- 建筑使用预渲染透明贴图；
- 清晰区分屋顶、正面、侧面和接触阴影；
- 形体简化，但立面细节完整；
- 使用中低饱和自然色，重点状态使用更高饱和度；
- 画面主要精致感来自资产本身，而非滤镜和浮层数量。

### 3.2 光照基线

- 主光源方向：左上方 35°～45°。
- 建筑右侧面比正面暗 8%～15%。
- 屋顶比正面亮 4%～10%。
- 接触阴影必须贴合建筑底部，不使用大面积悬浮阴影。
- 树木、车辆、棋子和路灯的阴影方向必须一致。
- 夜景、天气属于后续扩展，第一阶段只建立日间光照基线。

### 3.3 材质基线

| 材质 | 表现要求 |
|---|---|
| 墙面 | 哑光，轻微明暗变化，不使用纯色大平面 |
| 玻璃 | 青灰或灰蓝，保留少量高光，不做镜面反射 |
| 屋顶 | 明确厚度与边缘，允许少量设备和绿化 |
| 道路 | 冷灰蓝，车道线和斑马线清晰但不过亮 |
| 绿化 | 至少 3 个明度层级，树冠不能全部同形 |
| 水体 | 浅青蓝渐变，边缘有岸线和局部反光 |
| 金属 | 用于栏杆、路灯、招牌，避免大面积高光 |

## 4. 城市主场景构图

### 4.1 视觉层级

打开游戏后，视觉优先级必须是：

1. 当前玩家棋子和移动路径；
2. 当前即将结算的目标建筑；
3. 城市主场景；
4. 当前回合提示；
5. 其他玩家状态；
6. 次级装饰和背景动态。

### 4.2 主场景结构

完整地图采用闭环单向路径，但视觉上不能只画成标准方框。推荐：

- 外环道路承担大部分移动路径；
- 中央区域设置标志性建筑、公园、湖泊或公共广场；
- 起点与终点相邻，位于同一主要街区入口；
- 5 个地产价格带 A～E 通过街区氛围逐步升级；
- 后半圈建筑更高、商业密度更强，但道路和节点可读性保持一致；
- 重要建筑形成 3～5 个视觉锚点，避免平均分布导致无焦点。

### 4.3 路径表达

道路本身承担主要路径语义：

- 默认状态下，不显示连续的大圆点；
- 每格通过路面嵌入标记、建筑入口、路口铺装或小型地砖区分；
- 当前格显示柔和描边和地面光圈；
- 即将经过的路径逐段亮起；
- 经过后高亮快速衰减；
- 特殊格通过建筑和地面符号双重识别。

### 4.4 镜头

默认镜头应完整展示主要城市结构，同时保证棋子和建筑可辨认。

镜头行为：

- 投骰后，镜头在 180～260 ms 内平滑聚焦当前棋子；
- 移动过程中仅做轻微跟随，不反复大幅缩放；
- 到达目标后保留 300～500 ms 观察时间，再打开上下文面板；
- 玩家可双指缩放和平移，但决策弹窗打开时锁定场景误触；
- 提供“一键回到棋盘全景”。

## 5. 36 格的视觉语义

### 5.1 地格数量保持冻结

| 类型 | 数量 |
|---|---:|
| 起点 | 1 |
| 终点 | 1 |
| 地产 | 20 |
| 随机事件 | 5 |
| 卡片 | 2 |
| 股票市场 | 2 |
| 小游戏 | 2 |
| 监狱 | 1 |
| 公共设施 | 2 |
| 合计 | 36 |

### 5.2 特殊地格设计原则

特殊格必须做到：

- 只看建筑轮廓和地面标识即可识别类型；
- 建筑名称作为辅助，不作为唯一识别手段；
- 不依赖高饱和整块底色；
- 在棋子被建筑遮挡时，地面标识仍可识别。

### 5.3 类型映射

| 地格 | 城市场景表达 | 关键识别元素 |
|---|---|---|
| 起点 | 城市欢迎广场/车站入口 | 拱门、路牌、方向箭头、欢迎旗帜 |
| 终点 | 市中心庆典门/终点广场 | 金色路面纹章、庆典横幅，与起点相邻但形态不同 |
| 地产 | 住宅、商铺、酒店、办公楼等 | 独立建筑轮廓、价格带街区材质、所有权旗帜 |
| 事件 | 新闻站、公告广场、气象塔、施工点等 | 橙色公告标识、动态提示牌 |
| 卡片 | 邮局、幸运商店、礼品屋 | 卡片/信封符号、可开启的门窗或招牌 |
| 股票 | 证券交易所、商业中心 | 行情屏、柱廊、上升/下降符号 |
| 小游戏 | 游乐场、活动馆 | 彩旗、计时器、竞技入口 |
| 监狱 | 警署与拘留所 | 围栏、警灯、铁门；普通落点只显示“参观”状态 |
| 公共设施 | 市政服务中心、城市建设局 | 市政徽记、工程车辆或公共服务标识 |

## 6. 地产资产体系

### 6.1 地产区分方式

20 处地产不可使用同一个通用模型仅换颜色。采用：

- 10 个基础建筑家族；
- 每个家族至少 2 个立面或屋顶变体；
- 共形成 20 个可清晰区分的地产；
- 每处地产均输出 0～3 级四个正式状态。

共需至少：

```text
20 个地产 × 4 个等级 = 80 个正式建筑状态
```

### 6.2 五个价格带的街区语言

| 价格带 | 建筑语言 | 推荐类型 |
|---|---|---|
| A | 低层、温暖、社区感 | 咖啡店、小住宅、花店、面包房 |
| B | 更完整的商业立面 | 精品店、社区公寓、餐厅、书店 |
| C | 中层综合建筑 | 商住楼、酒店、公寓、创意园 |
| D | 高密度与现代感 | 商务楼、购物中心、高端酒店、展馆 |
| E | 城市地标级资产 | 总部大楼、豪华酒店、金融中心、观景塔 |

不同价格带通过建筑体量、窗墙比例、屋顶设备、门厅和景观升级体现，不通过单纯颜色深浅表达价值。

### 6.3 等级升级表现

| 等级 | 资产表现 |
|---|---|
| 0 | 完整基础建筑，无额外扩建 |
| 1 | 增加一层、侧翼、雨棚、招牌或小型景观 |
| 2 | 明显扩大体量，增加屋顶设施、露台或商业扩展 |
| 3 | 形成地标状态，轮廓变化明显，灯光和旗帜更完整 |

要求：

- 各等级必须在缩略尺寸下仍能区分；
- 不允许只增加数字徽章表示升级；
- 升级动画通过替换预渲染贴图完成；
- 同一建筑四级状态的脚底锚点必须一致。

### 6.4 所有权表达

所有权不改变建筑主体颜色，使用：

- 地产旗帜；
- 建筑入口前的小型玩家色标；
- 地产详情面板中的头像与色条；
- 当前收费时短时高亮。

玩家色仅作为状态色，不大面积染色建筑。

- 装饰层支持低性能模式减量。

## 9. 棋子设计

### 9.1 棋子数量

第一阶段准备 4 个角色棋子，对应最多 4 名玩家。

推荐方向：

- 猫咪邮差
- 兔子旅行家
- 小熊商人
- 柴犬探险家

角色可以调整，但必须满足：

- 轮廓差异明显；
- 远距离下能区分；
- 不依赖颜色区分玩家；
- 玩家色集中在底座、围巾、帽带或背包附件；
- 棋子脚底锚点一致。

### 9.2 棋子状态

每个棋子至少包含：

- idle：轻微呼吸或摆动；
- move：逐格跳跃/步行；
- celebrate：获得奖励；
- hit：支付高额费用或受到攻击；
- jailed：监狱状态；
- bankrupt：破产状态。

第一阶段技术切片只强制实现 idle、move、celebrate 三类。

## 10. UI 信息架构

### 10.1 常驻 UI

常驻元素只保留：

1. 其他玩家简略状态；
2. 当前玩家摘要；
3. 当前回合/阶段提示；
4. 手牌入口；
5. 骰子主操作；
6. 资产入口；
7. 系统菜单入口。

任何时刻，常驻 UI 不得遮挡超过约 22% 的有效棋盘面积。

### 10.2 页面层级

```text
Level 0  Phaser 城市场景
Level 1  场景内高亮、棋子、短时特效
Level 2  其他玩家简略状态
Level 3  当前玩家摘要与底部控制台
Level 4  Context Panel
Level 5  阻断 Modal
Level 6  Toast、金额飘字、短时结算结果
Level 7  系统级错误和恢复提示
```

### 10.3 常驻 HUD 布局

#### 其他玩家条

- 位于顶部或左上安全区；
- 每名玩家只展示头像、昵称、余额、地产数量、监狱/破产状态；
- 当前玩家不在此处重复展示完整信息；
- 2、3、4 人布局分别设计，不能依靠无限压缩。

#### 当前玩家摘要

- 位于左下安全区；
- 展示头像、昵称、余额、当前地格、持有卡片数量；
- 当前玩家色只用于边缘和头像底座；
- 允许点击展开完整资产面板。

#### 底部控制台

核心结构：

```text
手牌入口 | 当前状态提示 | 骰子主按钮 | 资产入口 | 辅助操作
```

骰子必须是唯一主视觉按钮，其他入口降低一级。

## 11. Context Panel

### 11.1 使用原则

- 同一时间最多出现一个主 Context Panel；
- 面板从右侧或底部进入，不同时出现多个白色浮层；
- 普通信息查看不阻断游戏；
- 需要玩家立即做决定时，才升级为 Modal。

### 11.2 面板类型

- PropertyPanel
- StockPanel
- ProjectPanel
- EventPanel
- JailPanel
- PaymentPanel
- AssetPanel
- RulesPanel

### 11.3 PropertyPanel

必须展示：

- 建筑正式缩略图；
- 地产名称与价格带；
- 当前所有者；
- 当前等级；
- 当前租金；
- 下一等级费用与租金；
- 0～3 级进度；
- 临时正负状态。

### 11.4 StockPanel

必须展示：

- 3 个可选股票；
- 500/1000/1500 万元投资档位；
- 2/4/6 大轮周期；
- 当前持仓数量与上限；
- “结果存在风险、不可提前卖出”的明确提示；
- 不展示隐藏判定数字。

### 11.5 EventPanel

- 使用场景插画或建筑局部作为主视觉；
- 标题不超过 12 个汉字；
- 结果文案一屏内读完；
- 金币变化、移动、状态变化使用不同结果样式；
- 不能用通用问号卡片替代所有事件表现。

---

## 12. 阻断 Modal

仅用于：

- 购买地产；
- 是否升级；
- 合作邀请；
- 防御响应；
- 手牌四选三；
- 监狱行动选择；
- 资产清算；
- 破产结果；
- 胜利结果。

### 12.1 Modal 规范

- 背景蒙层不超过 45% 黑色透明度；
- 保留部分城市可见，维持场景上下文；
- 主按钮位置稳定；
- 按钮文案使用动作，如“购买”“支付保释金”“使用防御”；
- 破坏性操作使用明确二次确认，但不滥用确认弹窗；
- 决策所需数据必须在同一视图中完整显示。

## 13. 核心组件规格

### 13.1 DicePrimaryAction

| 项目 | 规范 |
|---|---|
| 建议尺寸 | 88～104 px 主体，热区不小于 112 px |
| 默认态 | 立体骰子 + 当前操作文字 |
| 可点击态 | 柔和光圈与轻微呼吸 |
| 按下态 | 80～120 ms 下压 |
| 投掷态 | 禁止重复点击，显示滚动与等待 |
| 不可用态 | 降低饱和，不隐藏 |

### 13.2 PlayerChip

状态：

- 默认；
- 当前回合；
- 等待响应；
- 监狱；
- 破产；
- 刚获得/支付金额。

### 13.3 CardHandEntry

- 默认显示卡片数量；
- 存在可用卡时显示小型提示；
- 不在按钮外常驻展开全部手牌；
- 手牌展开后使用扇形或横向卡槽，最多 3 张；
- 抽到第 4 张时进入四选三阻断流程。

### 13.4 MoneyChange

- 收入：向上、绿色或青绿色；
- 支出：向下、珊瑚红；
- 玩家间转账：同时在付款方与收款方显示；
- 动画结束后金额显示必须与规则状态完全一致；
- 金额统一使用“万元/亿元”格式，不显示内部单位。

### 14.1 中性色

| Token | 用途 |

| Ink 900 | 主要文字与关键轮廓 |
| Ink 700 | 次级文字 |
| Ink 500 | 禁用文字、辅助线 |
| Surface 100 | 主面板 |
| Surface 200 | 次级容器 |
| Surface 300 | 分隔线 |
| Road 600 | 道路 |
| Road 300 | 道路线与斑马线 |

### 14.2 功能色

| Token | 用途 |
|---|---|
| Mint | 成功、收入、可用状态 |
| Blue | 信息、股票、当前路径 |
| Coral | 支出、攻击、风险 |
| Yellow | 奖励、卡片、提示 |
| Violet | 史诗、特殊项目 |

### 14.3 玩家色

玩家色必须在明度和色相上都可区分：

- P1：青绿
- P2：珊瑚橙
- P3：蓝紫
- P4：金黄

禁止仅依靠红绿差异传达玩家身份；头像、形状和编号作为辅助。

## 15. 字体与数字

### 15.1 字体层级

| 层级 | 建议字号 | 用途 |
|---|---:|---|
| Display | 36～44 | 胜利、破产、重大结算 |
| H1 | 28～32 | Modal 标题 |
| H2 | 22～26 | 面板标题 |
| Body | 16～18 | 正文与说明 |
| Label | 13～15 | 标签与次级数据 |
| Micro | 11～12 | 极少量辅助信息 |

真实 iPad 上不得以 11 px 以下文字承载关键信息。

### 15.2 金额格式

- 500 万元：`500万`
- 5000 万元：`5,000万`
- 12,500 万元：`1.25亿`
- 结算动画可以先显示完整万元，再归一化为亿单位；
- 小数最多两位，不显示无意义的 `.00`。

## 16. 动效系统

### 16.1 职责边界

| 引擎 | 负责内容 |
|---|---|
| Phaser Tween | 棋子、建筑、路径、骰子、镜头、粒子、场景对象 |
| Anime.js | Vue/DOM 面板、数字、卡片 UI、Toast、页面转场 |
| Rive（可选） | Logo、引导角色、重大结果等少量重点动画 |

同一对象不得同时由多个动画引擎控制。

### 16.2 动效时长

| 动效 | 时长 |
|---|---:|
| 按钮按下 | 80～120 ms |
| 小提示进入 | 140～220 ms |
| Context Panel | 180～260 ms |
| Modal | 220～320 ms |
| 棋子单步 | 180～240 ms |
| 镜头聚焦 | 180～300 ms |
| 购地升旗 | 350～600 ms |
| 建筑升级 | 700～1200 ms |
| 重大结算 | 600～1400 ms |

### 16.3 棋子移动

每一步包含：

1. 前一节点光圈亮起；
2. 棋子轻微抬升；
3. 沿路径移动；
4. 当前节点落地；
5. 落地压缩和小型尘埃；
6. 继续下一步。

完整移动可点击加速。加速只缩短表现，不改变结算顺序。

### 16.4 建筑升级

建议流程：

- 旧建筑轻微收缩；
- 施工烟尘遮挡切换；
- 替换到新等级贴图；
- 新建筑从 96% 放大到 100%；
- 玩家旗帜回弹；
- 显示等级提升结果。

不使用长时间逐层搭建动画。

### 16.5 减少动态

遵循系统 `prefers-reduced-motion`：

- 关闭循环漂浮；
- 棋子移动改为短位移淡入；
- 建筑升级改为交叉淡化；
- 减少粒子；
- 不影响规则和操作。

## 17. 资源输出规范

### 17.1 源文件

推荐：

- Blender：建筑和棋子建模、固定相机渲染；
- Illustrator/Figma：UI、地面标识、图标；
- Photoshop：贴图精修、阴影和色彩统一；
- Tiled：地图摆放和锚点配置。

### 17.2 运行时格式

| 资源 | 格式 |
|---|---|
| 建筑/棋子/装饰 | WebP 或 PNG 透明贴图 |
| 图标 | SVG 或纹理图集 |
| 地图 | Tiled JSON |
| 纹理图集描述 | JSON |
| 音效 | WebM/OGG + AAC 兼容备份 |
| 配置 | JSON/TypeScript |

### 17.3 建筑导出

- 透明背景；
- 统一相机角度；
- 统一世界单位到像素比例；
- 包含接触阴影，但阴影不得被裁切；
- 保留脚底锚点；
- 同一地产 0～3 级画布尺寸一致；
- 不在图片中写入地产名或价格。

### 17.4 纹理图集

建议分类：

```text

atlas-properties-b.webp/json

atlas-city-decor.webp/json
atlas-pawns.webp/json
atlas-effects.webp/json
atlas-ui-icons.webp/json
```

单张图集不超过移动 Safari 可稳定管理的合理尺寸。优先使用多个 2048 级图集，不使用超大整城贴图。

## 19. Tiled 图层契约

地图必须至少包含：

```text
ground
water
roads
road_markings
buildings_back
buildings_main
vegetation
city_decor
path_nodes
property_anchors
effect_anchors
foreground_occluders
```

规则数据不直接写进 Tiled。Tiled 仅保存：

- 对象位置；
- 贴图引用；
- 锚点；
- 遮挡层；
- 地图对象 ID。

地格类型、地产价格、触发方式等由 `game-content` 配置维护。

## 20. 设计令牌与组件实现

所有 UI 颜色、间距、圆角、阴影、层级和动效时间必须来自设计令牌。

禁止：

- 组件内部随意写十六进制颜色；
- 同类面板存在不同圆角；
- 按钮动效时间各自定义；
- 通过截图测量临时填值；
- 使用玩家色代替功能色。

设计令牌由 `packages/design-tokens` 输出，Vue 与 Phaser 都可读取。

## 21. 性能与质量预算

### 21.1 场景目标

- 目标设备：近几代 iPad Safari/PWA；
- 标准模式目标 60 FPS；
- 复杂结算允许短暂降帧，但交互不能卡死；
- 首屏关键资源优先加载，次级装饰延迟加载；
- 场景对象通过纹理图集和对象池复用；
- 不在每帧创建大量对象或数组；
- 不使用大量运行时模糊、发光和动态阴影。

### 21.2 视觉降级档位

| 模式 | 调整项 |
|---|---|
| 高质量 | 完整装饰、标准粒子、较高渲染比例 |
| 标准 | 默认粒子、标准装饰、适中渲染比例 |
| 节能 | 减少车辆/行人、关闭循环装饰、减少粒子和滤镜 |

核心建筑、棋子、路径和 UI 不得因性能模式丢失。

第一阶段不制作完整 36 格地图，只制作一段可验证的正式质量街区。

- 6 栋正式质量建筑；
- 道路、树木、车辆和公共小品；
- 1 个前景遮挡物，验证棋子遮挡关系。

- 2 人玩家 HUD；
- 当前玩家摘要；

- 资产入口；

- StockPanel；
- EventPanel；
- 购买地产 Modal；
- Toast 与金额变化；
- 动画加速按钮；

1. 隐藏 UI 后，街区本身仍是一张完整的微缩城市画面；

5. 常驻 UI 不抢占主场景；
6. 地产、股票、卡片、事件不看文字也有初步辨识度；
7. 动画可以跳过或加速；
8. 设计令牌真实用于组件，而不是仅写在文档中；
9. 资源替换不需要修改规则核心；
10. 不使用低质量通用几何建筑作为正式占位。

## 26. 最终判断标准

设计是否达标，不以“组件数量多”或“动画丰富”为判断依据，而以以下结果为准：

- 城市本身完整；
- 建筑具备独立设计；
- 道路就是棋盘；
- 信息一眼可读；
- 交互步骤简单；
- 视觉细节不简陋；
- UI 不压过场景；
- 规则状态与表现严格分离；
- 真实 iPad 上保持清晰、稳定和顺畅。
