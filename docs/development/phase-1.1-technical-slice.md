# Phase 1.1 八节点技术切片实现说明

## 1. 本阶段目标

本阶段验证正式技术架构能否承载已冻结规则，而不是交付完整36格游戏或最终美术。

验证对象：

- Phaser场景与Vue UI叠加；
- XState流程中断和恢复；
- 纯TypeScript规则核心；
- 逐格移动和路径触发；
- IndexedDB稳定节点快照；
- iPad横屏适配；
- `@bigmoney/*` Monorepo边界。

## 2. 八节点地图

顺序固定为：

```text
START
→ PROPERTY_A1
→ EVENT
→ STOCK
→ PROPERTY_A2
→ CARD
→ PROPERTY_A3
→ FINISH
→ START
```

跨圈奖励仅在 `FINISH → START` 时发放800万元。股票市场是路径触发；地产、事件和卡片是最终落点触发。

## 3. 已实现的规则切片

- 初始现金5000万元；
- 两名玩家；
- D6，每回合一次；
- 逐格移动；
- 股票市场展示3只股票，固定投资500/1000/1500万元，周期2/4/6大轮；
- 同一只股票持有期间不可重复购买，最多3笔持仓；
- 三处地产购买、升级和租金；
- 升级费60%/80%/100%；
- 租金10%/30%/70%/150%；
- 事件收入、支出和玩家转账示例；
- 卡片免费抽取；
- 当前技术切片采用“手牌满后抽1张，四选三弃1张”的暂定配置；
- 股票按冻结收益表在大轮结束时结算。

## 4. 暂未实现

以下系统不应在本阶段擅自补充：

- 强制付款后的完整降级、售地和破产链；
- 监狱；
- 合作项目；
- 完整卡牌攻击/防御窗口；
- 50条事件池；
- 6个小游戏；
- 36格正式地图；
- 正式建筑纹理图集和Tiled地图。

当前若租金或负面事件超过现金，规则核心会明确报错，避免产生错误的临时清算规则。

## 5. 技术数据流

```text
Vue操作
→ TechnicalSliceSession
→ XState阶段校验
→ executeCommand
→ GameState + DomainEvent
→ PresentationCue
→ Phaser动画
→ cue完成
→ XState继续
```

Game Core中不引用Phaser、Vue、XState、DOM或Canvas。

## 6. 场景实现

当前城市由程序化道路、绿化、装饰和八套SVG资产组合，作用是验证：

- 1194×834逻辑画布；
- 深度排序；
- 两名棋子同步；
- 骰子、逐格移动、地产旗帜和升级标记；
- Vue UI覆盖层。

这些SVG是技术切片资产，不代表最终视觉质量。后续正式美术应按设计规范输出透明WebP/纹理图集，并保持相同锚点接口。

## 7. 存档边界

只在 `turnReady` 稳定节点自动保存。保存内容包含：

- GameState；
- SeededRandom状态；
- 保存版本和时间。

领域事件独立写入日志。动画中间态不作为真实存档状态。

## 8. 本阶段完成条件

- `npm run check`通过；
- 两名玩家可持续轮流；
- 股票市场暂停后可继续剩余步数；
- 动画期间重复操作不造成重复结算；
- 刷新后可从稳定节点恢复；
- 场景对象按脚底Y值正确遮挡；
- 真实iPad Safari完成至少15分钟回归；
- GitHub Actions与Cloudflare Pages构建成功。
